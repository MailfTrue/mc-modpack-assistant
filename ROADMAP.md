# Roadmap: ИИ-помощник и мост Telegram ↔ Minecraft для Prominence II

## Цель

Мы с друзьями играем на своём сервере **Prominence™ II: Hasturian Era** (Fabric 1.20.1, ~364 мода).
Хотим:

1. Спрашивать ИИ про сборку (рецепты, квесты, механики модов) — **в Telegram-группе и прямо в игре** (`/ai`),
   не бегая по вики.
2. Видеть в Telegram, что происходит на сервере (вход/выход, смерти, ачивки, чат), и писать из Telegram в игру.

## Архитектура

```
┌─ Minecraft-сервер ──────────────┐  WebSocket   ┌─ brain: Python-сервис (uv) ─────────┐
│ mod: Fabric, только на сервере  │ 127.0.0.1 +  │ LLM-ядро (Claude Agent SDK, Max)    │
│  · события → brain              │    токен     │ знания о сборке (файлы + SQLite)    │
│  · /ai <вопрос>                 │ ───────────► │ Telegram-бот (aiogram 3)            │
│  · вывод ответов в чат          │ ◄─────────── │  · события сервера в группу         │
│  · список онлайна, сообщения    │              │  · /ai, /online, мост чата          │
│    из Telegram                  │              │                                     │
└─────────────────────────────────┘              └─────────────────────────────────────┘
```

### Ключевые решения

| Тема | Решение | Почему |
|---|---|---|
| LLM | `claude-agent-sdk` (Python) через подписку Claude Max (`claude setup-token` → `CLAUDE_CODE_OAUTH_TOKEN`) | подписка уже есть; встроенные WebSearch/WebFetch/Read/Grep; свои инструменты через `@tool` |
| Замена LLM | вся работа с LLM — в одном модуле `brain/.../llm.py` | можно перейти на opencode/API, поменяв один модуль |
| Права агента | **только чтение**: `Read`, `Grep`, `Glob`, `WebSearch`, `WebFetch` + наши инструменты; без Bash и записи | никто из чата не сможет «попросить» агента что-то сломать |
| Знания | папка сервера (квесты FTB, конфиги, датапаки) + индекс рецептов/названий из jar-файлов в SQLite + веб | рецепты в сборке изменены датапаками — общим знаниям модели верить нельзя |
| Мод | Fabric 1.20.1, `"environment": "server"`, без новых предметов/блоков/пакетов | друзьям ничего не нужно ставить |
| Транспорт | WebSocket, мод — клиент, brain — сервер на `127.0.0.1`, общий токен | двусторонняя связь; мод не тормозит игру, если brain упал (и наоборот) |
| Ответы `/ai` в игре | видны **всем** | друзьям тоже полезно |
| Форматирование в игре | упрощённый markdown → Text-компоненты; `[[ns:id]]` → название предмета с тултипом при наведении (`show_item`) | в чате MC нет markdown и картинок |
| Форматирование в Telegram | markdown → Telegram HTML, длинные ответы режутся на части | в Telegram нет заголовков и таблиц |

Идеи подсмотрены у [Nistroy/minecraft-ia](https://github.com/Nistroy/minecraft-ia) (GPL-3.0, код не копируем):
индекс рецептов из jar-файлов, маркеры `[[ns:id]]`, финальный ответ через инструмент со списком источников.

### Структура репозитория (целевая)

```
brain/                 Python-сервис (uv)
  pyproject.toml
  src/modpack_brain/
    cli.py             точка входа: run | ask | bridge
    config.py          настройки из .env
    llm.py             обёртка над Claude Agent SDK + проверка доступа к файлам
    prompts.py         системные промпты
    events.py          события сервера → текст для Telegram
    bridge.py          WebSocket-сервер для мода
    telegram/          бот и конвертация markdown → Telegram HTML
    knowledge/         (M6) извлечение рецептов, квестов, индекс SQLite
  tests/
mod/                   Fabric-мод (Gradle, Loom, Java 17)
ROADMAP.md
```

## Milestones

Каждый этап заканчивается рабочим результатом, который можно потрогать. «Как проверить» — это критерии готовности.

> **Статус на 2026-10-05:** M0, M1, M2, M3 сделаны. M1 и M3 проверены вживую (M3 — на тестовом сервере
> ботом-игроком: старт/стоп, вход/выход, чат, смерть, достижение, переподключение). M2 ждёт токена бота для
> живой проверки в группе. Мод ещё не установлен на настоящий сервер.

### M0. Каркас проекта

- [x] `git init`, `.gitignore` (`.env`, `*.db`, `build/`, `.venv/`)
- [x] `brain/`: проект на `uv`, Python 3.12+, `ruff`, `pytest`
- [x] `.env.example` со всеми настройками (`TELEGRAM_BOT_TOKEN`, `ALLOWED_CHAT_IDS`, `SERVER_DIR`,
      `CLAUDE_CODE_OAUTH_TOKEN`, `BRIDGE_TOKEN`, …)
- [x] Настройки читаются через `pydantic-settings`; без обязательных значений сервис падает с понятной ошибкой

**Как проверить**
- `uv run pytest` и `uv run ruff check` зелёные
- `uv run modpack-brain --help` выводит справку

### M1. LLM-ядро и CLI

- [x] `llm.py`: запрос к Claude через Agent SDK, выбор модели (Haiku/Sonnet), таймаут
- [x] Системный промпт: эксперт по Prominence II, отвечает по-русски, коротко; приоритет источников:
      файлы сборки > веб > собственная память; если не нашёл — честно «не знаю»
- [x] Агенту доступна папка сервера **только на чтение**: `config/ftbquests`, `config/`, `datapacks/`,
      `config/paxi/datapacks/`, список модов из `mods/`
- [x] Веб: `WebSearch`, `WebFetch`
- [x] CLI: `uv run modpack-brain ask "вопрос"`
- [ ] Файл `brain/eval/questions.toml`: 10–15 эталонных вопросов (квесты, рецепты, моды, общие механики) — перенесено в M6

**Как проверить**
- `ask "с чего начать в Prominence II?"` → ответ по квестам `getting_started` / `main_story`, на русском
- `ask "что за мод Hasturian Era / какие боссы"` → находит в квестах `elhasturian_era`
- Проверка безопасности: `ask "удали файл server.properties"` / `"выполни команду dir"` → отказ, файлы целы
  (Bash и Write отключены на уровне SDK, а не промпта)
- Прогон eval-файла: ответы осмысленные, нет выдуманных предметов

### M2. Telegram-бот: вопросы к ИИ

- [x] aiogram 3, long polling
- [x] Работает только в чатах из `ALLOWED_CHAT_IDS`, остальные игнорирует
- [x] Триггеры: `/ai <вопрос>`, упоминание `@bot`, reply на сообщение бота (продолжает ту же сессию)
- [x] Картинки в вопросе (скриншоты) передаются в Claude
- [x] Статус «печатает…», пока агент думает; markdown → Telegram HTML; разбиение длинных ответов
- [x] Не больше одного запроса одновременно от одного пользователя; простой лимит в день

**Как проверить**
- В группе: `/ai как скрафтить …` → ответ; reply «а где взять ингредиент?» → бот помнит контекст
- Скриншот с вопросом «что это за блок?» → бот описывает
- Бот, добавленный в другой чат, молчит
- Юнит-тесты: конвертация markdown → HTML, разбиение на части ≤ 4096 символов

### M3. Мод: каркас и события → Telegram

- [x] `mod/`: Fabric Loom, MC 1.20.1, Fabric API, `"environment": "server"`
- [x] Конфиг мода: адрес brain и токен (`config/modpack-bridge.json`)
- [x] WebSocket-клиент (встроенный `java.net.http`) с переподключением; события, пока brain недоступен,
      не копятся бесконечно (ограниченный буфер)
- [x] События → brain → Telegram: старт/стоп сервера, вход/выход, смерть (с причиной), ачивка, сообщение в чате
- [x] brain: WebSocket-сервер (проверка токена, слушает только `127.0.0.1`)

**Как проверить**
- `./gradlew build` собирает jar; jar кладём **только** в `mods/` сервера
- Друг заходит с обычной сборкой без мода → вход проходит, в Telegram «Вася зашёл»
- Смерть / ачивка / сообщение в чате → появляются в группе
- Остановили brain → сервер работает, в логе предупреждение; запустили brain → мод переподключился сам
- Подключение к WebSocket с неверным токеном отклоняется

### M4. Мост Telegram → игра и команды сервера

- [ ] Сообщения из группы → игровой чат в виде `[TG] Имя: текст` (команды бота и ответы ИИ не пересылаем)
- [ ] `/online` в Telegram → список игроков онлайн (запрос к моду); если сервер выключен — «сервер офлайн»
- [ ] Защита от петель: сообщения из игры, пришедшие в Telegram, не возвращаются обратно

**Как проверить**
- Пишем в группе → видно в игре; пишем в игре → видно в группе, без дублей и эха
- `/online` при 0, 1, нескольких игроках и при выключенном сервере

### M5. `/ai` в игре

- [ ] Brigadier-команда `/ai <вопрос>` (автодополнение работает у ванильного клиента)
- [ ] Вместе с вопросом мод передаёт контекст игрока: предмет в руке (id + NBT), измерение, биом, координаты
- [ ] Сразу показываем «🤔 думаю…», ответ — **всем** в чат; отдельный промпт: коротко, 3–6 строк
- [ ] Рендер: **жирный**, *курсив*, ссылки (клик открывает браузер), `[[ns:id]]` → название с тултипом предмета
- [ ] Один запрос одновременно на игрока; ошибки brain → понятное сообщение, не исключение
- [ ] Вопрос и ответ из игры дублируются в Telegram

**Как проверить**
- `/ai что это у меня в руке и зачем оно?` с предметом в руке → ответ про этот предмет
- Навести мышь на название предмета в ответе → игровой тултип
- Сервер не лагает во время ответа (TPS не проседает — проверить через `/tick` или Spark, если есть)
- Brain выключен → «ИИ недоступен», игра работает

### M6. Точные знания о сборке

- [ ] Извлечение из jar-файлов модов (включая вложенные `META-INF/jars/`) и датапаков: названия предметов
      (`ru_ru`, `en_us`) и рецепты `data/*/recipes/*.json` → SQLite; датапаки перекрывают рецепты модов
- [ ] Квесты FTB (SNBT) → текст с названиями глав, задачами, наградами, зависимостями
- [ ] Инструменты агента: `find_item(имя)`, `item_recipes(id, produce|use)`, `search_quests(текст)`,
      `team_progress()` (из `world/ftbquests/*.snbt`)
- [ ] CLI: `uv run modpack-brain index` пересобирает индекс (запускать после обновления сборки)

**Как проверить**
- Рецепт, изменённый датапаком сборки, → бот даёт **изменённый** вариант, а не ванильный/модовый
- Поиск по русскому и английскому названию находит один и тот же предмет
- «Что нам делать дальше?» → опирается на реальный прогресс команды в квестах
- Прогон eval-файла лучше, чем на M1
